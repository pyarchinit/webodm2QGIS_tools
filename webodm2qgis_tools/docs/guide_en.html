Experimental software, for QGIS 4. It can cause damage. Created by Luca Mandolesi of Flyoveracademy.it. Written entirely with Claude Code (Anthropic Claude Sonnet and Opus models). Provided without any warranty, use at your own risk: it writes files into the folder you choose and may overwrite files with the same name; it can change the CRS of the QGIS project and add many layers; it saves the server password in the QGIS authentication manager. Work on a copy of the project, make a backup and use a dedicated folder. It writes nothing to the WebODM server (read-only).

What it is

WebODM2QGIS-tools connects to a WebODM server (including the Windows app open on your PC) and brings task products into QGIS without the download → unzip → import routine: orthophotos, DSM/DTM, point clouds, photo shot points with one-click access to the original, and the products of the webodm-model-tools plugin (scaled or georeferenced cloud, shots and elevations). Before loading it checks EPSG, georeferencing and CRS and warns you about risks.

Installation

  • Requires QGIS 4 (Qt6). It does not work with QGIS 3.
  • From ZIP: Plugins → Manage and Install Plugins → Install from ZIP and choose webodm2qgis_tools.zip.
  • From source: copy the webodm2qgis_tools folder into %APPDATA%\QGIS\QGIS4\profiles\default\python\plugins and enable it in Manage and Install Plugins → Installed.
  • The WebODM menu, the WebODM toolbar and the panel on the left appear. The Guide button (in the panel and in the menu) opens this guide.

1. Connect to WebODM

Button «...» in the panel (or menu WebODM → Connect to WebODM). Enter address, user and password and press Save and connect. The password goes into the QGIS authentication manager (it asks for the master password), never into the project. For remote addresses use https: with http the password would travel in clear text and the plugin warns you.

WebODM Windows app open on your PC: press Local WebODM. The plugin fills in http://127.0.0.1:29800 (the app's server only listens on this computer) and checks that it is running. Then enter the user and password you use in the app (the app defaults are admin / admin, to be changed). The login is a separate access (JWT): the app window can stay open.

2. Choose project and task

The panel has the Project and Task lists, or Choose... for a window with search, status, photo count, preview and whether the task is georeferenced. Only completed tasks can be loaded.

3. Import session: name and folder

On the first load the plugin asks for a name and a folder. Files go to folder\name\task_id\..., the group in the Layers panel takes the session name and a sessione.json file lists what was imported. Name and folder are saved in the QGIS project and changed with Session....

4. Products and CRS traffic light

Select one or more products and press Load into project (or double-click). The dot tells whether there are warnings: green = none, yellow = read them, red = a decision is needed. The tooltip explains why. Downloads stream to file, can be cancelled and resume if interrupted.

Menu WebODM → Check project CRS: lists layers outside the project CRS, in degrees, without CRS or in a local CRS.

6. Photo shot points and originals

The Photo shot points product creates a point layer with an oriented arrow, elevation, orientation, camera, date and the originale field (?, si, no). To open the original photo: Photo tool (toolbar) — one click shows thumbnail and data, a double-click opens the original; or the QGIS «Run feature action» tool; or the Open original button.

  • Search order: local photo folder (if set), copy already downloaded in the session, server.
  • If the original is no longer on the server the field becomes no and it tells you, without errors. Verify all originals fills the field for the whole task.
  • Files over 30 MB ask for confirmation before downloading.

7. Photos that follow the model (scaled, rotated, georeferenced)

shots.geojson is in the original ODM frame. If you scaled, rotated or georeferenced the model with the WebODM plugin, the photos must be transformed with the same matrix to follow it. The Photos group offers three products:

  • Photo shot points: original frame (goes with the original cloud). In non-georeferenced tasks it uses the model's local metres, not the file's degrees (which would land at 0,0).
  • Shot points – georeferenced with the WebODM plugin, EPSG:xxxx: absolute coordinates (goes with the georeferenced cloud).
  • Shot points – scaled and oriented with the WebODM plugin: local coordinates, in the local CRS subgroup (goes with the scaled cloud).

The arrow directions also rotate with the model. If you change scale or georeferencing after the export, export again, otherwise cloud and photos will not match.

8. Shots and elevations from the WebODM plugin

The Shots and elevations tab shows thumbnails and data (view, size, scale 1:N, dpi, EPSG) of the shots made with the WebODM plugin.

  • Georeferenced plan: loaded in its real EPSG and overlays the rest.
  • Elevation, section or non-georeferenced plan: the GeoTIFF has image-plane coordinates in metres, not a position on Earth. It is loaded with a local CRS in a switched-off subgroup and opened in a separate map. The .points file comes along, for the QGIS Georeferencer.

Placing a shot on the canvas

With the shot loaded, turn the placement mode on and click a point on the QGIS canvas: the coordinates are captured (editable by hand) and Place here creates a georeferenced copy with the top-left corner on that point, in the project CRS (a light VRT file: no data copied, the original is left as it is). The project CRS must be projected in metres. It does not rotate or rescale the shot.

9. WebODM plugin exports and the georeferenced cloud

The WebODM plugin exports group lists the files saved with webodm-model-tools. The georeferenced cloud gets the EPSG chosen in the plugin's Georeferencing section: if the file has no CRS that one is assigned, without blocking you. The non-georeferenced scaled cloud has local coordinates: it goes in a local CRS, switched off, apart from the map.

10. WebODM viewer inside QGIS

Menu WebODM → WebODM viewer: 3D view, 2D map or dashboard of the task inside QGIS (QtWebEngine), with automatic login. If QtWebEngine is missing the system browser opens.

11. Language, About and warnings

Languages: Italian, English, French, German, Spanish, Portuguese. Choose in About → Language (automatic = QGIS language); it applies at the next start. This guide is in Italian and English.

Known limits

  • A session can hold several tasks, chosen one after the other.
  • Orthophoto streaming needs the password saved in the QGIS authentication manager (no token is written into the project).
  • Textured OBJ meshes are downloaded and unzipped but QGIS does not show them: use the WebODM 3D viewer.
  • The point cloud opens with QGIS's pdal provider, which indexes the file in the background.
  • Tested on QGIS 4.2 and on a fake WebODM server; the web viewer with a graphics card was not verified automatically.
